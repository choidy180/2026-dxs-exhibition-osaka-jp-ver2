# DX API 주소 선택과 BOM 조회 변경

## 접속 주소에 따른 API 선택

`utils/dx-api.ts`의 공통 함수가 **브라우저의 실제 origin(프로토콜·호스트·포트)** 으로 24828/gapi 대상 API 주소를 선택한다.

| 웹페이지 origin | DX API 기본 주소 |
| --- | --- |
| `http://192.168.2.147:3000` | `http://192.168.2.147:24828` |
| 그 외 모든 주소 | `https://gapi.dxsplatform.com` |

페이지 경로, `NODE_ENV`, 개발/운영 빌드 여부는 선택에 영향을 주지 않는다. 같은 IP라도 HTTPS나 다른 포트로 접속하면 외부 도메인을 사용한다. 기존 `NEXT_PUBLIC_DX_API_BASE_URL`, `NEXT_PUBLIC_DX_IMAGE_BASE_URL`, `NEXT_PUBLIC_LAB_API_BASE`, `NEXT_PUBLIC_PRODUCTION_PLAN_API_BASE`에 의한 주소 덮어쓰기는 제거했다.

- API 호출: `getDxApiUrl('/api/DX_API000026')`처럼 **요청 시점**에 호출한다. 모듈 상단에서 계산한 URL을 저장하지 않는다.
- 검사·이력·가이드 이미지: `resolveDxResourceUrl(path)`를 사용한다. 대상 DX 서버의 절대 주소와 상대 경로를 변환하며, 기존 이미지 응답의 구형 DX 호스트도 지원한다.
- 서버 코드: 브라우저 origin이 없으므로 `getDxApiUrl(path, requestOrigin)`처럼 요청 origin을 명시한다. 인수가 없는 서버 실행의 기본값은 외부 도메인이다. 현재 Next API 라우트에는 대상 DX API 직접 호출이 없다.
- Worker: 메인 스레드에서 선택한 URL을 메시지로 전달한다. Worker 내부에서는 `window.location`을 판단하지 않는다.
- 다른 서비스의 주소·포트(WebSocket, 영상 스트림, 별도 24830 API, AI Advisor 등)는 이번 DX 주소 선택의 대상이 아니다.

자재·운송·검사·생산·실험실·생산계획 및 백업 화면을 점검해 개별 주소 분기를 위 함수로 통합했다. Next 이미지 허용 목록에는 내부 이미지 서버와 외부 도메인을 모두 등록했다. 배포 서버에 적용하려면 변경 코드를 반영해 기존 절차로 빌드·재시작해야 한다.

### 기간별 입고 검수 현황은 기존 전용 API 유지

`/material/inbound-inspection/status`의 기간별 조회는 기존 `https://api.dxsplatform.com/api/V_PurchaseIn`을 사용한다. 주소 통합 과정에서 이 별도 서버를 gapi로 바꾼 오류를 복구했다. endpoint 경로가 같아도 응답 원천이 같다고 간주하면 안 된다. 이 전용 주소는 24828/gapi 전환 대상이 아니다.

2026-09-09 동일한 오늘 범위의 실측에서 gapi는 HTTP 200·빈 배열을 두 차례(394ms/300ms), 원래 api 서버는 HTTP 200·313건(1,204ms)을 반환했다. 복구 후 개발 브라우저에서 새로고침 버튼 없이 첫 접속으로 기존 기간·거래처 필터를 적용한 154건이 표시됐다. 운영 서버에 변경 코드를 배포한 결과는 아니다.

기존 화면이 조회 전/실패 시 표시하던 과거 예시 데이터를 제거했다. 브라우저 날짜 준비부터 실제 응답까지 로딩 상태를 표시하고, 빈 배열·요청 실패·잘못된 응답 형식을 구분한다. 최신 요청만 결과를 반영하며 30초 시간 제한·재시도·취소·이전 응답 무시를 처리한다. 코드 위치는 `constants/material-inbound-status.ts`, `hooks/use-inbound-status.ts`, `utils/material-inbound-status-api.ts`이다.

## `/lab/mes-bom-list`

조회조건은 적용일자·PJT코드·제품번호·발주구분 네 가지다. 적용일자와 PJT코드는 필수이고, 발주구분은 공백·발주·미발주를 선택한다. 공백은 발주구분을 제한하지 않는다. 실제 조회에서는 조건을 서버에 전달하고 응답을 그대로 표시한다. 목업에서만 PJT코드 정확 일치·제품번호 포함 검색을 적용한다.

입력 중인 조건과 마지막으로 조회한 조건을 분리한다. 필수값이 없으면 조회하지 않고 안내하며, 조건 변경 후 다시 조회하기 전에는 현재 조건 다운로드를 비활성화한다. 로딩·오류/재시도·빈 결과를 제공한다.

| 버튼 | 저장 범위 |
| --- | --- |
| 현재 조건 엑셀 다운로드 | 마지막으로 조회한 화면 결과의 행·열 |
| 전체 리스트 엑셀 다운로드 | 기존 `/api/DX_API000053/export`가 제공하는 전체 CSV 원본을 XLSX로 변환 |

두 다운로드는 Worker로 처리하며 진행·취소·재시도·중복 클릭 방지·시간 제한을 제공한다. 파일명으로 전체/현재조건을 구분한다. 현재 조건은 조회 전·조건 변경 중·로딩/오류·빈 결과에서 비활성화한다.

### 실제 BOM 조회 연결 (2026-09-11)

API 서버의 [API Explorer](https://gapi.dxsplatform.com/docs)에서 확인한 `GET /api/DX_API000053/`으로 연결한다. 기존 `/api/DX_API000201`은 HTTP 404를 반환하는 임시 주소였으며, 실제 모드의 조회 함수도 요청 없이 오류를 내고 있었다.

| 화면 조건 | API 쿼리 |
| --- | --- |
| 적용일자 | `AdaptDate` (`YYYY-MM-DD`) |
| PJT코드 | `PrjCode` |
| 제품번호 | `ItemCode` (입력한 경우) |
| 발주구분 | `PurType` (발주/미발주를 선택한 경우) |

BOM 목록은 기본적으로 실제 API를 사용한다. `NEXT_PUBLIC_LAB_USE_MOCK=true`를 명시하면 기존 개발용 데이터를 사용하며, 발주대상 등 다른 실험실 화면의 기본 목업 설정은 유지한다. 목업에는 `2026-07-27` 기준 `ET-09057`만 있으므로 실제 PJT코드로 검색하면 결과가 없었다.

`utils/lab-api.ts`에서 MES 응답 필드를 화면 타입으로 변환한다. 실제 결과의 `baseDate`는 요청한 적용일자이며, 목업 고정 기준일 비교나 클라이언트의 추가 조건 필터를 적용하지 않는다. 요청 취소·90초 시간 제한·한국어 오류 안내와 재시도를 제공한다. API 오류를 목업이나 빈 결과로 바꾸지 않는다.

실제 응답의 `BomLevel`은 `0`, `.1`, `..2`처럼 점으로 계층을 표시하므로 점 접두어를 제거해 숫자 레벨로 변환한다. 초기 직접 점검에서는 HTTP 502도 발생했지만, 후속 실제 요청에서는 `2026-07-27`·`ET-09057` 조건으로 HTTP 200·765건을 확인했다. 문서만으로 서버 장애를 단정하지 않으며 느린 응답과 오류를 구분한다.

**현재 조건 Excel과 전체 Excel은 출력 열과 조회 범위가 다르다.** 화면의 모든 행이 조회됐다는 이유만으로 두 파일이 같다고 판단하지 않는다. 두 다운로드가 동일한 원본·기준 시점·출력 열을 사용하도록 통일하는 작업은 별도 미완료 항목이다.

## 확인한 범위 (2026-09-09)

- 공통 주소 함수와 실제 API 설정 함수: origin 변경, SSR import 후 호출, 경로/쿼리 보존, 이미지·별도 서비스 보존을 네트워크 없는 격리 검증으로 확인했다.
- 외부 도메인의 가스켓 `DX_API000026`, 필름 `DX_API000027`, 발포 `DX_API000025`: 모두 HTTP 200 JSON 응답 헤더 확인(약 0.33~0.43초). 전체 응답 내용의 업무 정확성까지 검증한 결과는 아니다.
- 내부 서버 점검은 연결 시간 초과로 실제 운영 브라우저에서의 호출을 확인하지 못했다. 외부 BOM 전체 조회/내보내기는 15초 점검 내 응답을 받지 못했으며, 대용량 다운로드 최종 실패로 단정하지 않는다.
- BOM 목업 조회·현재 조건 XLSX 생성·취소·오류/재시도 및 이전 응답 무시를 검증했다. 전체 원본 API와 화면의 데이터 대조는 미확인이다.
- 실제 Chrome에서 필수값 안내, 발주구분 세 옵션, 조건 변경, 다른 목업 날짜의 빈 결과를 확인했다. 현재 조건 다운로드 파일을 다시 열어 90행·14열·수식 셀 0개를 확인했다. 1920·1500·1200 CSS 픽셀에서 페이지 넘침이 없었고 검사 후 뷰포트 설정을 복원했다.
- `npx tsc --noEmit` 통과. 공통 주소·BOM 주요 변경 13파일의 ESLint 오류/경고는 0개다. 전체 `npm run lint`는 기존 코드 문제를 포함한 오류 86개·경고 62개로 실패했다(작업 전 89개·63개).
- 실제 운영 서버 배포·재시작은 수행하지 않았다.
