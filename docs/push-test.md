# 고모텍 CCTV — 내부망 푸시 테스트

`/lab/push`는 **고모텍 CCTV**의 로그인 화면과 모바일용 CCTV 목록을 제공한다. 로그인 후 상단의 **CCTV Push ON/OFF**로 테스트 알림을 제어하고, 아래 목록에서 카메라를 누르면 해당 영상 하나만 연결한다. 가상 알림은 실제 카메라 목록·상태·영상과 연결되지 않는다. 원본 `/lab/cctv-monitoring`의 동작은 유지된다.

별도 APK로 설치하는 갤럭시 앱은 [갤럭시 CCTV 테스트 앱](push-test-android.md)을 참고한다. 기존 PWA와 계정·예약 저장소를 공유하며, APK 알림은 네이티브 FCM으로 수신한다.

회사 현장에서 전달할 안내서는 다음 두 파일이다. **Windows PC 서버 실행 + 갤럭시 Chrome 웹앱(PWA) 설치**를 기준으로 하며, CA 인증서 설치 오류와 해결 절차를 포함한다. 별도 APK 설치 안내서가 아니다.

## PC 패키지 설치

처음 준비하는 PC이거나 프로젝트의 패키지 설정이 바뀌었으면 프로젝트 폴더에서 설치를 실행한다. Windows x64와 Node.js 24에서 확인한 명령이다.

```powershell
cd D:\dev\2026-mode-dxs
npm.cmd install
```

`better-sqlite3 13.0.3`은 Windows에서 포함된 실행 파일이 있어도 `node-gyp rebuild`를 호출하여 Python을 찾다가 실패하는 [설치 문제](https://github.com/WiseLibs/better-sqlite3/issues/1516)가 보고되어 있다. 이 프로젝트는 해당 문제를 피하도록 `12.11.1`에 고정했다. 같은 오류가 나면 갱신된 `package.json`과 `package-lock.json`을 함께 받은 뒤 위 명령을 다시 실행한다. 이 버전은 지원 환경에서 미리 빌드된 파일을 내려받으므로 GitHub 다운로드 연결이 필요하다. 다른 환경이나 다운로드 실패로 소스 빌드가 필요한 경우에는 별도 빌드 도구가 필요할 수 있다.

## Windows 컴퓨터 + 갤럭시에서 처음 테스트하기

처음 한 번은 휴대폰에 테스트용 인증서를 설치한다. 이후에는 컴퓨터에서 실행 명령을 켜고, 갤럭시 Chrome에서 출력된 주소로 들어가면 된다. 회사에서 이미 사용하는 HTTPS 테스트 서버가 있다면 아래의 서버 설정 절차를 사용한다.

PC의 기존 벽면 랜선 연결을 유지할 때는 **Windows 모바일 핫스팟**도 사용할 수 있다. PC에서 `Win+I` → **네트워크 및 인터넷 → 모바일 핫스팟**을 열고, 공유할 인터넷 연결을 **이더넷**, 공유 방법을 **Wi-Fi**로 선택한다. 핫스팟을 켠 뒤 같은 화면의 네트워크 이름과 암호를 확인하고, 갤럭시 Wi-Fi 목록에서 그 이름을 선택해 연결한다. PC는 유선 인터넷을 유지하고 휴대폰이 PC의 무선 연결을 사용한다. 이 경우 아래 1번을 대신한 것이므로 2번부터 진행한다. 핫스팟 활성화 후 실제 할당된 사설 주소를 실행 명령이 선택하며, 주소를 미리 특정 값으로 가정하지 않는다. 가상 어댑터 등의 주소가 여러 개라면 핫스팟의 실제 주소를 선택한다. [Microsoft 모바일 핫스팟 안내](https://support.microsoft.com/ko-kr/windows/experience/connectivity-networking/use-your-windows-device-as-a-mobile-hotspot)

1. **컴퓨터와 갤럭시를 같은 공유기에 연결한다.** 갤럭시는 설정 → 연결 → Wi-Fi에서 연결하고, 컴퓨터는 같은 Wi-Fi에 연결하거나 그 공유기에 랜선을 연결한다. LTE/5G만 켠 휴대폰으로는 이 내부 주소에 접속할 수 없다. 인터넷이 되는 내부 네트워크를 사용한다.
2. **컴퓨터에서 PowerShell을 연다.** Windows 시작 버튼을 누르고 `PowerShell`을 검색해 실행한다. 열린 창에 다음 명령을 한 줄씩 붙여넣고 Enter를 누른다.

   ```powershell
   cd D:\dev\2026-mode-dxs
   npm run push:phone
   ```

   이 프로젝트 폴더에 Node와 패키지가 설치되어 있다는 기준이다. 설정 파일 `.env.push-test.local`이 있으면 자동으로 읽으므로 다시 생성하거나 파일을 옮길 필요가 없다. 설정이 없다는 안내가 나올 때만 `npm run push:setup -- --phone`을 먼저 실행한다. 이때 주소는 자동으로 정해지고, 테스트 로그인 ID(예: `pushtest`), 본인이 정한 비밀번호(빈 값 제외), `mailto:` 뒤에 본인 이메일 주소를 입력한다. 이메일을 발송하거나 메일 로그인을 요구하는 기능이 아니다. 생성 후 `npm run push:phone`을 다시 실행한다.
3. 첫 실행에서는 컴퓨터용 테스트 인증서를 준비한다. Windows에서 인증서 설치 확인 창이 나타나면 이 테스트용 설치인지 확인하고 진행한다. 잠시 후 `접속 주소:`와 `휴대폰 인증서 다운로드:`가 표시된다. **`Ready`가 나올 때까지 기다리고 이 PowerShell 창은 계속 켜 둔다.** 표시되는 접속 주소가 실제 입력할 주소이며, 문서의 예시 주소를 입력하는 것이 아니다. 주소는 실행할 때 현재 컴퓨터의 내부 주소로 자동 설정되고 기존 비밀키와 계정 파일은 유지된다.
4. **컴퓨터에서 화면을 확인한다.** Chrome을 열고 `Ctrl+L`을 누른다. Chrome 맨 위의 긴 입력칸이 선택되면 `접속 주소:` 뒤의 `https://`부터 `/lab/push`까지 전체를 붙여넣고 Enter를 누른다. 인증서 설치 직후라면 Chrome을 모두 닫고 다시 열어야 할 수 있다.
5. **갤럭시에 인증서를 한 번 설치한다.** 갤럭시 Chrome의 주소창에 실행 창의 **휴대폰 인증서 다운로드** 주소를 그대로 입력한다. `push-test-ca.crt` 파일이 다운로드된다. 갤럭시 **설정 → 보안 및 개인정보 보호 → 기타 보안 설정 → 기기에 저장된 인증서 설치 → CA 인증서**에서 **Download** 폴더의 이 파일을 선택한다. 기종에 따라 메뉴 이름이 다르면 설정 검색에서 **인증서 설치**를 찾는다. 휴대폰 잠금 비밀번호를 요구할 수 있다. 이 파일은 컴퓨터의 테스트 사이트를 신뢰하게 하는 공개 인증서이며 다운로드만으로 자동 설치되지는 않는다. 브라우저에서 다운로드가 차단된다면 기존 USB 파일 전송 방식으로 `D:\dev\2026-mode-dxs\.data\push-test-ca.crt` 파일 하나를 휴대폰 Download 폴더로 옮긴다. [mkcert 공식 휴대폰 안내](https://github.com/FiloSottile/mkcert#mobile-devices)
6. **갤럭시에서 페이지를 연다.** Chrome 앱을 실행하고 화면 위 주소 입력칸을 누른다. 컴퓨터에 표시된 **같은 접속 주소 전체**를 입력하고 이동을 누른다. 휴대폰에는 `localhost`를 입력하지 않는다. 인증서 경고 없이 **고모텍 CCTV** 로그인 화면이 보여야 한다. 기존 로그인 세션이 유지되어 있으면 CCTV 목록으로 바로 들어간다.
7. **앱 설치 → 로그인 → 푸시 알림 ON을 진행한다.** 페이지의 **앱 설치** 또는 Chrome 메뉴로 설치한다. 메뉴는 **⋮ → 설치 및 바로가기 만들기 → 설치**, **앱 설치**, **홈 화면에 추가** 등으로 표시될 수 있다. 설치한 **고모텍 CCTV**를 열고 설정할 때 정한 ID/비밀번호로 **로그인**한다. 로그인만으로 새 알림 등록이나 발송을 시작하지 않는다. 목록 위의 **CCTV Push**을 **ON**으로 바꾸고, 처음 나타나는 알림 요청에서 **허용**을 누른다. 등록이 성공하면 서버가 즉시 첫 알림을 발송하고 이후 10초 간격으로 반복한다. 제목은 **고모텍 CCTV**, 본문은 **`123번 CCTV 영상 수신 오류가 발생했습니다. (test)`** 형식이며 번호는 매번 1~200 중 무작위로 정한다. 실제 CCTV 장애를 뜻하지 않는다. 앱을 닫거나 화면을 잠가도 **PC 서버와 워커를 켜 둔 동안** 발송하며, **OFF**로 바꾸면 현재 기기의 반복 발송을 중지한다. OS·네트워크 상황에 따라 실제 수신 간격은 달라질 수 있다. [Chrome 설치 안내](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=ko)

문제가 생겼을 때:

- **“휴대폰에서 접속할 내부 주소가 없습니다”**: 이 간편 실행 명령에서 허용하는 사설 IPv4 주소가 현재 컴퓨터에 없다는 뜻이다. 유선 연결도 사용할 수 있다. PC를 휴대폰이 사용하는 공유기의 LAN 포트에 연결하거나 같은 Wi-Fi에 연결해 사설 주소를 받은 다음 `npm run push:phone`을 다시 실행한다. 회사 배선은 네트워크 관리자에게 휴대폰 Wi-Fi와 통신 가능한 내부 유선망 연결을 요청한다. 공인 주소 대역을 내부에서 사용하는 망도 있으므로, 주소 대역이 다르다는 이유만으로 통신 불가능하다고 단정하지 않는다. 이 명령은 공인 주소나 모든 네트워크에 서버를 열지 않는다.
- **PowerShell에서 npm.ps1을 실행할 수 없다는 오류**: `npm.cmd run push:phone`으로 실행한다. Windows 실행 정책을 변경할 필요는 없다.
- **“내부 주소가 여러 개입니다”**: 출력된 후보 중 갤럭시와 같은 공유기에 연결된 컴퓨터 주소를 골라 `npm run push:phone -- --host=선택한주소`로 실행한다.
- **주소 사용 중 / EADDRINUSE**: 이전에 켜 둔 개발 서버 창에서 `Ctrl+C`를 눌러 종료하고 다시 실행한다. 다른 포트가 필요하면 PowerShell에서 `$env:PORT='3001'`을 입력한 뒤 다시 실행한다. 새로 출력된 접속 주소를 사용한다.
- **컴퓨터에서는 열리지만 휴대폰에서는 연결 시간 초과**: 같은 Wi-Fi인지 확인한다. Windows 방화벽의 Node.js 연결 허용 창이 뜬 경우 신뢰하는 **개인 네트워크**만 허용한다. 회사 Wi-Fi가 기기끼리의 연결을 막는 경우 내부망 관리자가 허용해야 한다. 방화벽 전체를 끄거나 공유기 포트포워딩을 설정하지 않는다.
- **개인정보 보호/인증서 경고**: 5번의 인증서 설치와 6번의 주소를 확인한다. 경고 화면을 건너뛰는 것으로 대체하지 않는다.
- **“CA 인증서를 설치할 수 없음” / “null 인증서가 설정에 설치되어 있어야 합니다”**: 브라우저나 파일 열기에서 CA 설치를 시도하면 Android에서 표시할 수 있는 메시지다. 확인을 눌러 닫고 갤럭시 **설정 → 보안 및 개인정보 보호 → 기타 보안 설정 → 기기에 저장된 인증서 설치 → CA 인증서**로 이동한다. 여기에서 **Download → push-test-ca.crt**를 선택한다. 파일이 목록에 있으면 다시 다운로드할 필요가 없다. 설치 후 브라우저를 완전히 종료하고 HTTPS 테스트 주소를 다시 연다. Android 11 이상에서는 일반 앱의 CA 설치 요청 대신 설정 앱을 통한 설치가 필요하다. [Android KeyChain 안내](https://developer.android.com/reference/android/security/KeyChain)
- **알림이 안 옴**: 로그인 후 **CCTV Push ON**인지 확인하고, 컴퓨터 실행 창을 유지한다. 갤럭시의 방해 금지 모드, 앱/Chrome 알림 허용, 인터넷 연결을 확인한다. 발송 실패로 반복이 중지되었다면 원인을 해결한 뒤 화면에서 상태를 다시 확인하고 **ON**으로 시작한다.

로컬 HTTPS는 설치된 Next.js의 개발용 HTTPS 기능을 사용한다. 인증서 신뢰 설치와 같은 네트워크 연결은 실제 장치에서 진행해야 하며, 이 문서만으로 설치·수신이 검증된 것은 아니다. **갤럭시 접속, 설치, 잠금 후 실제 푸시 수신: 실기기 검증 필요.** 테스트를 끝낼 때는 **CCTV Push OFF** 후 PowerShell에서 `Ctrl+C`를 누른다. 필요하면 갤럭시 사용자 인증서 목록에서 이번 테스트 인증서도 삭제한다.

## 장소·서버 PC를 바꿀 때

1. 이동 전에 기존 앱에서 **CCTV Push를 OFF로 끈 다음**, PC 서버 창에서 **`Ctrl+C`**로 종료한다. 서버 창만 닫으면 저장된 반복 설정과 예약이 남아 재시작 후 발송이 재개될 수 있다. 기존 주소에 접속할 수 없다면 이전 서버 담당자에게 발송 중지를 요청한다.
2. 새 장소에서 PC와 갤럭시를 통신 가능한 내부망에 연결하고 `npm run push:phone`을 다시 실행한다. 예전 아이콘이나 예시 IP 대신 **새 실행 창에 표시된 현재 HTTPS 주소**로 접속한다. 로그인 상태를 확인하고 필요한 경우 다시 로그인한 뒤 ON으로 알림을 등록한다. 이전 아이콘이 옛 주소를 열면 새 주소에서 웹앱을 다시 설치한다.
3. **같은 PC에서 IP만 바뀌고 기존 CA가 유지되었다면** 휴대폰 CA를 무조건 재설치할 필요는 없다. 현재 주소가 인증서 경고 없이 열리는지 확인한다.
4. **다른 PC를 사용하거나 CA를 새로 만들었다면** 현재 서버가 제공하는 `push-test-ca.crt`를 받아 설정에서 CA 인증서로 설치한다. 파일 이름이 같아도 인증서 내용은 다를 수 있다. 설치 후 경고가 남으면 Chrome을 완전히 종료했다 다시 열고 현재 주소를 확인한다.

## 테스트 서버 설정

이 저장소에는 기존 로그인/서버 세션과 서버용 DB가 없어 테스트 페이지에만 별도 계정 인증과 SQLite 저장소를 추가했다. 계정 ID는 서버 설정에서 정하며, 구독은 인증된 사용자와 서명된 현재 브라우저 기기 쿠키에 함께 묶인다. 세션은 12시간, 기기 식별은 180일 유지된다. 계정/키 설정을 변경하면 다시 로그인 또는 알림 재등록이 필요할 수 있다.

1. Node.js 22 이상(현재 개발 환경: 24)에서 `npm install` 후 `npm run push:setup`을 실행한다. 내부 HTTPS origin, 테스트 계정, 비밀번호, 관리자 연락처를 입력한다. 비밀번호 입력은 숨겨지고 해시만 저장한다.
2. 생성된 `.env.push-test.local`은 `push:dev`, `push:start`, `push:phone`, `push:worker`에서 자동으로 읽는다. 기존 서버 환경변수와 `.env.local` 값이 우선하며, 일반 `npm run dev/start`에는 전용 파일을 적용하지 않는다. 서버 환경변수로 직접 설정해도 된다. 비밀키와 세션 비밀값에는 `NEXT_PUBLIC_`을 붙이지 않는다.
3. `npm run build` 후 `npm run push:start`를 실행한다. 개발 중에는 `npm run push:dev`를 사용할 수 있다. 이 명령은 웹 서버와 독립 워커를 함께 유지하고 종료된 자식 프로세스를 재시작한다. 웹 서버는 로컬 `127.0.0.1`에 바인딩한다.
4. 서버 재부팅 후에도 같은 작업 디렉터리에서 명령이 실행되도록 기존 서비스 관리자(systemd/Windows 작업 스케줄러 등)에 등록한다. 셸 종료에 의존하지 않는 상시 실행이 필요하다. 기존 웹 서버 실행 방식을 유지하려면 `npm run push:worker`를 별도 상시 서비스로 실행한다.

| 환경변수 | 설정 |
| --- | --- |
| `APP_ENV` | `test` |
| `PUSH_TEST_ENABLED` | `true` — 두 활성화 값 중 하나라도 다르면 페이지·API·manifest·SW·아이콘은 404, 워커는 실행 거부 |
| `PUSH_TEST_ORIGIN` | `https://dxs-test.internal`처럼 경로 없는 내부 HTTPS 주소, 브라우저 주소와 정확히 일치 |
| `PUSH_TEST_VAPID_PUBLIC_KEY` | 생성한 공개키, 등록 API가 클라이언트에 제공 |
| `PUSH_TEST_VAPID_PRIVATE_KEY` | 생성한 비밀키, 서버 전용 |
| `PUSH_TEST_VAPID_SUBJECT` | `mailto:관리자메일` |
| `PUSH_TEST_SESSION_SECRET` | 32바이트 이상 무작위 비밀값, 웹 서버 재시작 시 동일하게 유지 |
| `PUSH_TEST_USERS_JSON` | `{"tester":"salt:scrypt해시"}` 형태. setup 명령으로 생성. 평문 비밀번호를 넣지 않음 |
| `PUSH_TEST_DB_PATH` | 기본 `./.data/push-test.sqlite`, 웹 서버·워커가 공유하는 **영속 로컬 디스크**의 같은 절대경로 권장 |

SQLite 파일과 `-wal`/`-shm` 파일은 웹 공개 디렉터리에 두지 않고 서비스 계정만 읽도록 관리한다. 컨테이너 사용 시 디스크 볼륨을 유지한다. 이 구성은 동일 호스트의 지속 실행 Node 서버용이며, 요청 종료 후 프로세스가 중지되는 서버리스나 여러 호스트의 공유 네트워크 파일시스템용이 아니다.

## HTTPS와 내부망

### 여러 사람이 간단하게 테스트하려면

서버에 휴대폰이 기본 신뢰하는 HTTPS 인증서를 적용하면 테스트 참여자는 별도 CA 인증서를 설치할 필요 없이 내부 주소 접속 → 앱 설치 → 로그인 → **CCTV Push ON** 순서로 진행할 수 있다. 실제 보유 도메인과 해당 도메인의 DNS 설정 권한이 필요하다. 공개 인증기관의 DNS-01 검증과 내부 DNS를 사용하면 CCTV 서버를 인터넷에 공개하지 않고 인증서를 발급받을 수 있다. 회사에서 이미 신뢰되는 내부 HTTPS 주소를 제공한다면 이를 우선 사용한다. 현재 개발용 사설 IP 주소에 인증서 다운로드 버튼을 추가하는 것만으로 이 신뢰 설정이 대체되지는 않는다. [Let's Encrypt DNS-01 안내](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge)

현재 `push:phone`의 USB 없는 파일 전달은 개발용 편의 기능이다. 웹 포트의 다음 포트(기본 3001)에 사설 IP로만 연결하는 HTTP 서버를 열고 `/lab/push/test-ca.crt`에서 공개 CA 인증서 하나만 제공한다. 다른 경로와 앱·API·CCTV 영상은 제공하지 않는다. HTTPS의 같은 경로도 인증서 다운로드를 제공한다. `/lab/push`의 **앱 설치** 안내에 **휴대폰 인증서 받기** 링크가 표시된다. 인증서 설치 전에는 PC 실행 창의 HTTP 다운로드 주소를 휴대폰 Chrome 주소창에 직접 입력한다. 서버가 내부적으로 지정하는 `PUSH_TEST_LOCAL_CERTIFICATE` 및 `PUSH_TEST_CERTIFICATE_DOWNLOAD_URL` 값은 사용자가 따로 만들 필요가 없다. 일반 `push:dev/start`에서는 이 편의 기능이 켜지지 않는다.

처음 설정하는 휴대폰에는 HTTP 다운로드 주소를 Chrome 주소창에 직접 입력한다. HTTPS 페이지에서 HTTP 파일 다운로드를 시작하면 브라우저의 혼합 다운로드 제한에 걸릴 수 있고, 자체 인증서 HTTPS 페이지는 신뢰 설정 전에 경고를 만날 수 있다. 다운로드 차단이나 인증서 경고를 무시하도록 요구하지 않으며, 그런 환경에서는 USB 전달 또는 신뢰되는 HTTPS 주소를 사용한다. [Chrome 다운로드 안내](https://support.google.com/chrome/answer/6261569?hl=ko)

- 휴대폰이 신뢰하는 인증서와 내부 DNS를 사용해 기존 사내 리버스 프록시에서 HTTPS를 종료하고 로컬 Next 서버로 전달한다. 사설 CA라면 휴대폰에도 해당 CA를 신뢰하도록 등록해야 한다. 인증서 경고를 무시하는 것만으로 PWA 동작은 보장되지 않는다.
- 테스트 PC의 `localhost`와 휴대폰에서 사용하는 내부 주소는 서로 다르다. 휴대폰의 실제 HTTPS origin을 `PUSH_TEST_ORIGIN`에 넣는다.
- CCTV API와 WHEP는 기존 동일 출처 프록시를 그대로 사용한다. 영상 미디어 연결은 계속 내부망에서만 가능하다. 서비스 워커에는 fetch 핸들러/오프라인 캐시가 없어 CCTV 영상과 API 응답을 저장하지 않는다.
- 서버와 휴대폰은 사용하는 브라우저의 푸시 서비스(Google/Apple/Mozilla 등)에 **외부로 나가는 HTTPS** 연결이 가능해야 한다. 내부 사이트를 인터넷에 공개할 필요는 없다. 외부 공개, VPN, 터널, 포트포워딩 구성은 포함하지 않았다.
- 알림 데이터에 제목·본문이 들어 있으므로 휴대폰은 표시할 때 내부 서버를 조회하지 않는다. 알림 클릭은 `/lab/push`로 이동하며 외부망에서는 그 페이지가 열리지 않을 수 있다.

## 휴대폰 확인 순서 — 실기기 검증 필요

1. 내부 Wi-Fi에서 `https://내부주소/lab/push`를 연다. **고모텍 CCTV** 로그인 화면을 확인한다.
2. **앱 설치**를 누른다. Android의 지원 브라우저에서는 설치 창/메뉴를 사용한다. iPhone·iPad는 Safari의 공유 → 홈 화면에 추가 후 홈 화면의 앱을 실행한다. iOS/iPadOS 16.4 이상이 필요하다. [WebKit 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)
3. 설정한 테스트 계정으로 **로그인**한다. 로그인은 계정과 기존 상태만 확인하며, 새 권한 요청·기기 등록·반복 발송을 시작하지 않는다. 이전에 ON으로 켜 둔 반복 발송은 계속되며 화면에도 기존 상태가 표시된다. 로그인 후 실제 CCTV 목록, 이름·번호·위치 검색, **전체 / 확인 필요** 필터와 카메라 선택 시 영상이 열리는지 확인한다.
4. **CCTV Push**을 **ON**으로 바꾸고 처음 나타나는 알림 권한 요청에서 **허용**을 누른다. 첫 알림의 즉시 발송과 이후 10초 간격의 반복 발송을 확인한다. 번호는 1~200 중 매번 무작위이며 제목은 **고모텍 CCTV**, 본문은 **`번호번 CCTV 영상 수신 오류가 발생했습니다. (test)`** 형식이다. 앱을 닫거나 화면을 잠근 상태에서도 수신되는지 확인한다. PC 서버·워커와 인터넷 연결이 필요하며, 브라우저/OS·네트워크에 따라 실제 표시가 지연될 수 있다. 권한을 차단했다면 기기 설정에서 허용한 뒤 다시 시도한다.
5. 알림을 눌러 `/lab/push`가 열리는지 확인한다. 내부망 밖에서는 페이지가 열리지 않을 수 있다.
6. **CCTV Push OFF**로 바꾸고 이후 반복 발송이 중지되는지 확인한다. 서버의 현재 기기 반복 설정과 미발송 예약을 취소한 다음 기기 구독을 해제한다. 이미 푸시 서비스에 전달한 알림은 OFF 직후에도 도착할 수 있다. 다른 휴대폰의 구독에 영향을 주지 않는지도 확인한다.

## 예약·장애 처리

현재 기기의 반복 설정, 예약 시간과 가상 메시지를 SQLite 트랜잭션에 저장한다. ON 요청은 첫 알림을 지연 없이 예약한다. 1초 주기로 동작하는 별도 워커가 도래한 예약을 가져와 발송하고, 성공하면 그 시점으로부터 10초 뒤의 다음 알림 한 건을 예약한다. 브라우저의 `setInterval`에 의존하지 않으므로 앱을 닫거나 화면을 잠가도 PC 서버·워커가 실행 중이면 계속 발송한다. PC를 끄거나 워커를 종료하면 발송되지 않는다. 재시작 시 유효한 미발송 예약을 이어서 처리하되, 중단 기간의 알림을 여러 건 쌓아 한꺼번에 보내지는 않는다. 최근 워커 heartbeat가 없으면 새 예약은 거부한다.

중복 ON 요청과 다중 탭 요청은 같은 활성 예약을 반환한다. OFF는 서버 반복 설정과 미발송 예약을 취소한 후 기기 구독을 해제한다. 푸시 서비스에 이미 발송을 시작한 알림은 회수할 수 없다. 발송이 실패하거나 결과가 불명확하면 반복을 중지한다. 전송 중 강제 종료/네트워크 응답 유실은 중복 발송을 피하려고 같은 알림을 자동 재시도하지 않고 `unknown`으로 기록한다. `sent`는 푸시 서비스 접수 성공이며 휴대폰 표시 확인을 의미하지 않는다. 만료된 구독은 정리하고 재등록을 안내한다.

`lib/push-test/send.ts`의 발송 함수는 독립되어 있으며, 실제 장애 이벤트 연동은 구현하지 않았다. 서비스 워커/manifest는 `/lab/push`에만 한정한다. 기존에 다른 서비스 워커가 이 경로를 차지하면 덮어쓰지 않고 오류를 안내한다. [Next.js PWA 가이드](https://nextjs.org/docs/app/guides/progressive-web-apps), [web-push 라이브러리](https://github.com/web-push-libs/web-push)

## 코드 검증

`npm run test:push`, `npx tsc --noEmit`, `npm run lint`로 예약·인증·기기 격리·서비스 워커와 정적 검사를 실행한다. 자동 검사의 푸시 전송부는 대체 전송 함수를 사용하며 실제 브라우저 푸시 서비스나 휴대폰 수신 성공을 대신하지 않는다. 실제 HTTPS 인증서, 휴대폰 설치/권한, 잠금·종료 후 수신, 내부망 CCTV 영상 연결은 **실기기 검증 필요**.
