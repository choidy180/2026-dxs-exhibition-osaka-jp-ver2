# 운송 배경지도 설정과 표시 스타일

2026-09-09 운송 실시간 현황의 지도에서 반복되던 `API KEY REQUIRED`는 CARTO 지도 타일에 포함된 인증 안내였다. 운송 API의 차량·배차 데이터와는 별개 요청이다. 기존 운영 2D, 3D, 레거시 2D 모두 API 키 없이 CARTO의 `voyager_nolabels` 주소를 호출했다.

[CARTO 공식 안내](https://carto.com/basemaps/apikey/)에 따르면 이제 베이스맵 요청에 키가 필요하다. 인증 문구는 받은 이미지 안에 있으므로 CSS나 마커 설정을 바꿔 해결할 수 없다.

## 현재 동작

- **2D**는 OpenFreeMap의 OpenMapTiles 벡터 데이터를 OpenLayers로 직접 그린다. 일반 내비게이션처럼 고속도로·간선도로는 연노랑, 일반도로는 흰색과 옅은 테두리, 물은 연파랑, 공원은 연녹색으로 구분한다. 주거·산업 구역도 낮은 채도의 면으로 표시한다. 산림 전체·봉우리 아이콘·등고선·상점 아이콘은 숨긴다. 차량·시설·운행 경로는 별도 레이어로 유지된다.
- 기본 화면은 기존 운송 구간과 확대 수준(최대 12)을 유지한다. 사용자가 최대 16까지 확대할 수 있으며, 확대 수준에 따라 도로명·동네명·이면도로·건물 윤곽이 추가된다. 글자는 한국어 우선이고 충돌하는 이름은 생략한다. 벡터 데이터의 최대 줌은 공급자에 맞춰 14로 유지하며 더 큰 화면 확대에서는 기존 타일을 확대해 그린다.
- 공개 TileJSON에서 최신 PBF 주소를 읽으므로 날짜별 타일 경로를 코드에 고정하지 않는다. 새 지도 라이브러리나 API 키는 필요하지 않다. 운영 2D와 레거시 2D에 동일하게 적용하며 벡터 배경이 차량 클릭 판정을 가로채지 않도록 차량 레이어만 선택 대상으로 제한한다.
- **3D**는 기존 OpenStreetMap 래스터 바닥을 유지하고 배경 이미지에만 저채도·밝기 보정을 적용한다. 별도로 만들었던 장식용 산·나무·녹지·물가를 제거하고 바닥·조명·건물을 중립색으로 정리했다. 래스터 원본에 포함된 실제 숲·지명 등은 개별 제거되지 않고 옅게 남는다.
- 공급자와 출처 설정은 `constants/transport-basemap.ts`, 2D 스타일은 `utils/transport-map-style.ts`, 지도 색과 내부 그리기 순서는 `styles/design-tokens.ts`의 `mapPalette`·`mapLayer`에서 관리한다.
- 화면 아래에 실제 공급자의 출처 링크를 항상 표시한다. 2D의 1200 이하 화면은 왼쪽 아래에 배치한다.
- 배경지도 로딩 중 안내와 로딩 실패 시 **지도 재시도**를 제공한다. 2D는 타일 목록의 HTTP·JSON·형식 오류, 빈 목록, 요청 취소와 재시도를 처리한다. 3D도 일부 타일이 빠지면 오류를 표시하고 전체 성공일 때만 로딩을 완료한다. 15초 동안 응답이 없으면 오류 안내를 표시한다. 2D는 이후 모든 타일이 정상 도착하면 오류 안내도 해제한다.
- 차량·시설 마커, 운행 경로, 배차 API와 기존 2D/3D 전환 동작은 유지한다. 배경지도 성공이 운송 API의 성공을 의미하지 않으며 그 반대도 마찬가지다.

## 3D 바닥에 CARTO를 사용할 경우

해당 사이트에 사용할 공식 CARTO 베이스맵 키가 있다면 `.env.local` 또는 빌드 환경에 다음 값을 지정한다.

```dotenv
NEXT_PUBLIC_CARTO_BASEMAP_API_KEY=해당_사이트의_공식_베이스맵_키
```

개발 서버를 다시 시작하고 배포 환경은 재빌드한다. 유효한 키를 설정하면 3D 바닥이 CARTO를 사용하고 출처에도 CARTO가 추가된다. 2D는 단순화 스타일을 유지하기 위해 OpenFreeMap을 사용한다. 이 값은 브라우저 요청에 포함되는 공개 베이스맵용 키다. 서버 전용 비밀 키를 넣으면 안 된다. 키 발급·도메인·사용량·상업 이용 조건은 CARTO 정책에 따른다. 현재 작업에서는 새 계정을 만들거나 키를 발급받지 않았고, 유효한 CARTO 키를 사용한 실요청은 검증하지 않았다.

## 내부망 및 운영 조건

현재 공개 지도는 브라우저에서 2D `https://tiles.openfreemap.org`, 3D `https://tile.openstreetmap.org`로 접속할 수 있어야 한다. 완전히 차단된 내부망에서는 별도의 사내 지도 타일 서비스가 필요하다. 지도는 회사의 운송 데이터가 아니라 화면 범위의 배경 타일 좌표만 요청한다.

[OpenFreeMap 공식 안내](https://openfreemap.org/)에 따르면 공개 서비스는 등록·키 없이 사용할 수 있고 상업 이용도 허용된다. 대체 클라이언트에서는 출처를 표시해야 하므로 OpenFreeMap·OpenMapTiles·OpenStreetMap 링크를 지도에 표시한다. [공식 빠른 시작](https://openfreemap.org/quick_start/)과 [OpenMapTiles 스키마](https://openmaptiles.org/schema/)를 기준으로 허용 레이어를 정했다.

[OpenStreetMap 타일 사용 정책](https://operations.osmfoundation.org/policies/tiles/)에 맞춰 브라우저의 기본 HTTP 캐시와 리퍼러를 유지한다. 강제 캐시 우회·오프라인 저장·넓은 지역 사전 다운로드는 하지 않는다. 2D는 현재 화면 범위, 3D는 현재 장면의 고정 8타일만 요청한다. 공개 타일 서버는 SLA가 없는 서비스이므로 대규모 관제 운영이나 가용성 보장이 필요하면 사용량에 맞는 지도 공급자 또는 자체 호스팅을 선택해야 한다.

## 인증 문구 해결 시 확인한 결과

실제 Chrome의 `/transport/realtime-status`에서 OpenStreetMap 2D 배경, 인증 문구 제거, 시설·차량·경로 유지, 지도 출처 링크를 확인했다. 3D도 타일 로딩 오류 없이 전환됐고 공통 출처가 표시됐다. 지도 제공업체 교체로 실제 도로·운송 데이터의 정확성을 새로 검증한 것은 아니다.

공급자·키 설정 16개 검증, 2D 타일 훅 16개 시나리오, 3D 텍스처 훅 57개 검증이 통과했다. 네트워크를 일부러 차단하지 않고 격리 검사로 부분 실패·15초 제한·늦은 완료·재시도·이전 요청·Strict Mode·자원 정리를 검증했다. `npx tsc --noEmit`와 신규 코드·3D 컴포넌트 ESLint는 통과했다. 전체 `npm run lint`는 기존과 동일한 오류 89개·경고 63개이며, 레거시 2D 컴포넌트의 기존 린트 문제도 남아 있다.

## 지도 단순화 후 확인한 결과

2026-09-09 실제 Chrome에서 2D 산·숲·관심 지점 제거, 중립색 도로·물, 한국어 지명, 차량 클릭 상세, 2D/3D 전환을 확인했다. 3D에서는 장식 산·나무가 제거되고 배경 채도가 낮아졌다. 바닥 받침이 텍스처 평면을 가리던 높이도 조정해 지도 이미지가 정상적으로 보이도록 했다.

1920·1500·1200 CSS 픽셀에서 가로 넘침 없이 지도와 출처가 표시됐다. 1200 이하에서는 2D 출처를 왼쪽 아래로 옮겨 하단 지도 설정에 가려지지 않도록 했으며 실제 링크의 클릭 영역도 확인했다. 임시 화면 크기와 검사 탭은 정리했다.

OpenFreeMap의 실제 TileJSON·지역 PBF 요청에서 HTTP 200과 CORS 허용을 확인했다. 새 2D 벡터 훅 32개 시나리오와 실제 OpenLayers 객체를 사용한 스타일 검사 76개가 통과했다. 최종 타입 검사와 신규·분리 코드 및 3D ESLint는 통과했고, 전체 린트는 기존 오류 89개·경고 63개로 동일하다. 지도 공급자는 외부 공개 서비스이며 사내망 전체의 접속 정책을 검증한 것은 아니다.

## 내비게이션 스타일 재조정

같은 날 지나치게 단조롭다는 피드백을 반영해 위의 현재 2D 스타일로 조정했다. 실측 지역 타일에서 공원이 `landcover`의 `grass/park`, 동 이름이 `place`의 `quarter`로 제공됨을 확인하고 확대 수준별로 표시했다. 산림은 계속 숨기며 주요도로와 일반도로의 색·굵기, 생활권의 면, 물의 색으로 위치를 구분한다.

실제 Chrome에서 기본 운송 구간, 한국어 도로명, 확대 시 건물 윤곽과 세부 도로, 차량 클릭·선택 해제, 지도 로딩 완료를 확인했다. 실제 지역 PBF를 최신 스타일 함수에 적용한 15개 검사와 최종 타입 검사·스타일/토큰/설정 ESLint가 통과했다. 전체 린트는 기존 오류 89개·경고 63개로 동일하다. 앞선 회색 스타일의 76개 검사는 이전 단계의 기록이며 현재 스타일은 새 15개 검사와 화면 확인으로 검증했다.
