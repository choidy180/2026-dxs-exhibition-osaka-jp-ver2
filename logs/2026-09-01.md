## 09:45:44 KST — CCTV 카메라 클릭 시 WebSocket 실시간 영상 재생 구현

- AI 도구: Claude
- 간단한 작업 내용: `/lab/cctv-monitoring` 에서 카메라를 클릭해 크게 보면 정지 썸네일 대신 WebSocket 실시간 영상이 나오도록 만들었습니다. 메시지 한 건이 JPEG 한 장인 방식입니다.
- 자세한 작업 내용:
  - 기존 코드는 WHEP(WebRTC) 를 전제로 `whepBaseUrl`, `webrtcPath` 를 읽고 있었습니다. 실제 API 계약(`streamPath`, WebSocket JPEG)에 맞춰 타입과 매핑을 교체했습니다.
  - WebSocket 은 Next.js 라우트로 중계할 수 없어 브라우저가 사내 서버에 직접 붙어야 합니다. 다만 사내 주소는 서버 전용 설정이라 클라이언트가 알 수 없었습니다. 그래서 목록 프록시 응답에 `streamBaseUrl` 을 추가하고, 그 값을 사내 API 주소에서 파생시키도록 했습니다. 주소를 한 곳에서만 관리하게 되어 API 주소를 바꾸면 스트림 주소도 함께 따라갑니다.
  - 실시간 재생 훅을 새로 만들었습니다. WebSocket 을 열어 이진 메시지를 JPEG Blob 으로 만들고 Blob URL 로 바꿔 `<img>` 에 물립니다. 문자열 메시지나 빈 메시지는 프레임으로 처리하지 않습니다.
  - 메모리 누수를 막기 위해 프레임 URL 을 최대 2개만 유지합니다. 화면에 붙어 있는 것과 새로 들어온 것만 남기고 그 이전 URL 은 해제해, 해제가 너무 일러 발생하는 깜빡임도 함께 피했습니다.
  - 연결이 끊기면 2초 간격으로 최대 5회까지 자동 재연결합니다. 재연결 중에는 마지막 프레임을 그대로 두어 화면이 검게 비지 않습니다. 첫 프레임이 10초, 재생 중 프레임이 8초 동안 없으면 신호 없음으로 안내합니다.
  - 모달을 닫거나 다른 카메라로 바꾸면 소켓을 닫고 타이머와 Blob URL 을 정리합니다. 정리 도중 들어오는 이벤트로 상태가 다시 바뀌지 않도록 핸들러를 먼저 떼고, 늦게 도착한 이벤트는 어느 스트림의 결과인지 확인해 무시합니다.
  - HTTPS 페이지에서는 브라우저가 `ws://` 를 혼합 콘텐츠로 차단하므로, 연결을 시도하기 전에 걸러 원인을 안내합니다.
  - 실시간 재생 컴포넌트를 새로 만들어 연결 중·신호 없음·오류 상태를 화면 위에 겹쳐 보여주고 '다시 연결' 버튼을 제공합니다. 재생 중에는 LIVE 배지와 수신 프레임 수를 표시합니다.
  - 프로젝트 규칙상 effect 본문에서 상태를 바로 바꿀 수 없어, 초기 상태는 파생값으로 계산하고 실제 연결은 콜백에서 시작하도록 구성했습니다.
  - 썸네일은 기존 구현이 이미 `thumbnailUrl` 에 `?v={thumbnailVersion}` 을 붙여 캐시를 갱신하고 있어 그대로 두었습니다.
